; pointer.txt - TWO hires frames, 24x21 each, carrying the classic arrow-pointer
;   silhouette (the shape of the X11 left_ptr cursor). Drawn as TWO SPRITES
;   overlaid at the same window position: that is how a hires pointer gets an
;   outline WITHOUT giving up half its resolution to multicolour, and it works
;   because the two frames never set the same pixel --
;
;     frame 0  the FILL    -- the interior, 1px inside the silhouette
;     frame 1  the OUTLINE -- the ring around it
;
;   Sprite 1 shows frame 1 (the ring) and takes the ink; sprite 0 shows frame 0
;   (the interior) and takes the canvas background, so the arrow reads as an
;   outline with the canvas showing through it. Because the frames are disjoint,
;   no two sprites ever compete for a pixel, so the sprite-priority rule does not
;   come into it at all.
;
;   The TIP is the sprite box's top-left pixel: the canvas coordinate the user is
;   pointing at is (sprite x - 24, sprite y - 50) -- the window's left edge is
;   sprite x = 24 and its first raster line is sprite y = 50 (docs/lib-sprite.md).
;
; Authored here and converted by tools/gen-sprites.py; the .spr is committed
; beside it, so a fresh clone builds without Python (the same arrangement as the
; charsets and the banners).
